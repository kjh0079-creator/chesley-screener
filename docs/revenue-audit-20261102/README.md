# 체슬리 스크리너 매출 성장률 수정과 판정 영향

2026년 11월 2일 검증. 비교 기준 코드는 `afca0ebc3b627011bc416fde29925d525b89de67`입니다.

## 수정 내용

- 최신 분기 매출과 전년 같은 분기 매출로 `(최신 매출 - 전년 동기 매출) / 전년 동기 매출 × 100`을 계산합니다.
- 재무제표를 결산일 내림차순으로 정렬하고 전년 결산일과 대조합니다. 52·53주 회계연도에 따른 이동을 고려해 최대 7일 차이를 허용합니다. 비교 후보가 여러 개면 계산을 보류합니다. 다섯 번째 열을 무조건 사용하는 방식이 아닙니다.
- 전년 매출이 없거나 0 이하, 최신 매출이 없거나 음수, NaN·무한대 등 유효하지 않은 값이면 `rev_growth_yoy=None`과 사유를 반환합니다. 최신 매출 0과 양수인 전년 매출은 유효한 -100%입니다.
- 임의 성장률 15%와 이전 분기로의 대체를 없앴습니다. 데이터가 부족하면 성장률 조건은 False, 최종 통과는 False, CANSLIM은 None입니다. 확인되지 않은 성장률로 점수를 산정하지 않습니다.
- 20% 필터, CANSLIM 성장 점수, 화면 합격 표시 모두 같은 반올림 전 YoY를 사용합니다. 19.96%가 표시 반올림 때문에 20% 합격으로 바뀌지 않습니다.
- 화면은 음수에 잘못된 `+`를 붙이지 않으며, 계산 불가 사유와 비교 결산일을 표시합니다.
- 고정 종목 목록과 히스토리는 실시간 계산 결과와 구분되도록 안내를 추가했습니다.

## 실제 종목 영향 비교

기존 고정 목록 22개 티커의 Yahoo Finance 데이터를 yfinance 1.7.0으로 2026년 11월 2일 10:14 KST에 조회했습니다. 각 티커의 정보·분기 재무제표·현금흐름을 한 번 저장한 후 동일한 입력을 구·신 엔진에 넣었습니다. 결과 비교 중에는 다시 네트워크 조회를 하지 않았습니다.

- 비교 성공 22개, 조회 또는 계산 실패 0개.
- 20% 성장률 조건 변화 14개.
- CANSLIM 점수 변화 16개.
- 최종 파트2 판정 변화 8개. 최종 통과는 기존 코드 2개에서 수정 코드 10개로 변경됐습니다.
- 미통과에서 통과로 바뀐 티커: U, FSLY, STLN, XMTR, BRZE, MP, LASR, TTAN.
- 예: U는 기존 표시 7.5%(실제 QoQ)에서 YoY 23.93%로, CANSLIM은 76.5점에서 89.0점으로 변경됐습니다.

## 검증과 재현

Python 3.12, pandas 2.2.3, numpy 2.3.5, yfinance 1.7.0, Streamlit 1.66.1에서 검증했습니다.

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

결과: **76 passed**. 합성 재무제표로 잘못된 통과와 잘못된 탈락, 분기 누락, 비교 매출 0·음수·NaN·무한대, 최신 매출 누락, 결산일 순서, 비달력 회계연도, 53주·윤년, 20% 및 CANSLIM 경계값을 검증했습니다. 이 중 22개 테스트는 저장한 실제 티커 스냅샷 재계산, 5개는 전체 Streamlit 앱의 계산·화면 연동 검사입니다. 테스트에는 외부 재무 데이터 조회가 필요하지 않습니다.

```bash
python tools/audit_revenue_growth.py \
  --snapshots docs/revenue-audit-20261102/snapshots.json \
  --output /tmp/chesley-audit-replay
```

스냅샷 재실행으로 comparison.csv의 바이트 단위 일치와 같은 집계를 확인했습니다. 재실행 도구는 기존 커밋을 git에서 읽으므로 해당 커밋 이력이 필요합니다. 새로 복제한 저장소에서는 일반 git clone을 사용하거나 해당 이력을 먼저 가져오면 됩니다.

```bash
python tools/audit_revenue_growth.py --output /tmp/chesley-live-audit
```

위 명령은 현재 데이터로 새 감사를 수행합니다. 가격·시총·신규 실적 공시 등에 따라 결과가 달라질 수 있습니다. GitHub Actions에 오프라인 회귀 테스트를 추가했으며 push와 pull request에 실행되도록 구성했습니다.
